① 意圖清單

  • 給誰用：你＋同事／業務幾個人（不開客戶入口）
  • 用來做什麼：開報價單給客戶、查報過的價、盯已送出的報價單；成交的報價單轉成訂單、管到交付
  • 做完會得到：客人問舊價 30 秒內答得出；每天打開就知道該追哪幾張；新報價單 5 分鐘開完、PDF 拿得出手
  • 絕不能發生：①總額跟明細對不起來 ②送出的報價單被悄悄改 ③同事動別人的報價單而沒紀錄

② 主流程（七步）

  1. 開新報價單、挑客戶（清單裡沒有→填名字＋電話存成新客戶，繼續開單）
  2. 填明細：挑商品或自由填品名、數量、單價（明細存快照）；總額自動算、不給手改
  3. 送出：產生體面 PDF 自己傳（LINE／email）；之後可改但留紀錄
  4. 列表盯已送出的報價單：掛越久排越上、越顯眼
  5. 點成交／沒成
  6. 成交的報價單轉成訂單：待處理 → 處理中 → 完成
  7. 查舊價：搜客戶或品名，翻出歷次報價單（搜尋在列表裡）

③ 核心物件（八種）

使用者、客戶、商品、報價單、報價明細、訂單、訂單明細、修改紀錄

④ 暫不實作

  • 通知／提醒（推播類）——他來找系統，系統不推
  • 「幾天算掉出視線」的天數——做列表時再定

這個系統是什麼（四問）

  • 給誰用：你＋同事／業務幾個人（不開客戶入口）。
  • 用來做什麼：開報價單給客戶、查報過的價、盯已送出的報價單；成交的報價單轉成訂單、管到交付。

退路（每一步都可退一格、退也留紀錄）：

  • 已送出 →（收回）→ 草擬——客戶手上那份 PDF 視為作廢，重送出新版
  • 已成交／沒成 →（點錯改回）→ 已送出
  • 訂單 →（作廢）→ 報價單回到 已成交（訂單留一筆作廢紀錄，不真刪）
  • 訂單推進也退一格：處理中 →（退回）→ 待處理、完成 →（點錯改回）→ 處理中——同樣留紀錄（作廢只從 待處理 走；已開工的先退回再作廢）
  • 送出後的報價單可改，每次修改記進修改紀錄（不鎖單）。
  • 有效期限過了不跑排程改狀態，查詢時現算「剩幾天」。

權限

  • 要登入才能開單（帳號先由開發者手建——照知識架構圖使用者模組）；沒登入呼叫建立相關 API 一律擋下。
  • 負責人自動＝登入的人，不能挑別人（架構圖資料表：負責人＝開單的人）。
  • v1 登入的人權限都一樣（誰都能開單）；要分角色時先回架構圖改。

驗收（每條都要能跑出來看）

  1. 挑一個客戶、填兩行明細（2×1000、1×500），存檔 → 總額顯示 2500，狀態是 草擬，單號長得像 Q20260814-001。
  2. 改第一行數量成 3 → 總額自己變成 3500，沒有任何地方可以手動改總額。
  3. 明細一行都沒有就想存 → 被擋下，而且看得懂為什麼。
  4. 數量填 0 或負數 → 被擋下。
  5. 同一天連開三張 → 流水號 -001、-002、-003，不重複。
  6. 有效期限填成昨天 → 詳細頁顯示已過期（狀態不會自己變）。
  7. 未登入呼叫建立端點 → 被擋下（401/導去登入）。
  8. 登入 A 帳號開單 → 這張單的負責人顯示 A，且沒有任何地方可以改成別人。
