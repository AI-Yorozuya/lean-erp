# 功能規格書 — 送出與收回

> 模組：報價單／動作：送出（含收回）（主流程③）
> 只講「送出（含收回）」這一個動作。狀態、原則、資料的定義都在[知識架構圖](架構圖.md)——這裡引用、不重抄。

## 這個動作在做什麼

草稿確認沒問題，按「送出」：狀態 `草擬`→`已送出`、蓋送出日、產生一份體面的 PDF 讓老闆自己傳（LINE／email）。送錯了按「收回」退回草擬，客戶手上那份 PDF 視為作廢、重送出新版。

**修改紀錄從這個動作開始建**（架構圖・操作紀錄模組）：從送出起，每筆改動都記「誰、何時、哪張單、改了什麼」——含狀態退回。點結果、轉單都用同一套紀錄，不各做一份。

## 權限

- **送出後改明細是允許的，但每次都留紀錄**（[架構圖原則 2](架構圖.md)）——不鎖單，鎖的是歷史。
- 登入的人都能送出／收回；**動到別人負責的單也可以，但紀錄會寫明是誰做的**（[架構圖原則 3](架構圖.md)）。v1 不做角色限制。

## 驗收（每條都要能跑出來看）

1. 草擬單按送出 → 狀態 `已送出`、送出日＝今天、拿到一份打得開的 PDF（含明細與總額）。
2. 已送出的單改一行明細 → 修改紀錄多一筆（誰、何時、改了什麼）。
3. B 帳號改 A 負責的單 → 修改紀錄標的是 B（原則 3）。
4. 按收回 → 狀態回 `草擬`、留一筆「收回」紀錄（原則 4：狀態退回也是修改）。
5. 草擬單看不到「收回」、已送出的單看不到「送出」（狀態不對的動作不出現）。

## 施工順序

修改紀錄 model → 送出／收回（狀態＋紀錄）→ PDF → 驗收變測試 → 畫面。

## 對應實作

- API：`POST /api/v1/quotations/{id}/send`、`POST /api/v1/quotations/{id}/recall`、`GET /api/v1/quotations/{id}/pdf`；修改紀錄在 `apps/changelog/`（`record()` 是唯一寫入口），報價單詳細的 `logs` 欄帶出來
- 測試：`apps/lean-backend/apps/quotations/tests_send.py`——驗收 5 條＋收回再送出蓋新日期＋編輯存檔一筆紀錄
- 畫面：報價單詳細頁表頭「送出／收回」、右上「報價單 PDF」、頁底「修改紀錄」
- PDF：`apps/quotations/pdf.py`，中文字型內嵌（Docker 映像裝 fonts-wqy-zenhei）
