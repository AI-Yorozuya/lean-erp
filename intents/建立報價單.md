# 功能規格書 — 建立報價單

> 從[架構圖](架構圖.md)切一塊放大。窄而深：只講這一個動作，講到可以施工、可以驗收。
> 規格從架構圖長出來，不從畫面長出來——畫面是最後才碰的東西。

## 這一塊在做什麼

老闆接到詢價，開一張報價單：挑客戶、一行一行填要報什麼、系統把錢算出來，先存成草稿，之後再送出。

## 欄位

**單頭**

| 欄位 | 必填 | 說明 |
|---|---|---|
| 客戶 | ✅ | 從既有客戶挑；找不到就當場建一筆 |
| 單號 | 自動 | `Q` + 日期 + 三碼流水（例 `Q20260814-001`），不可改 |
| 狀態 | 自動 | 新建一律 `草擬` |
| 有效期限 | — | 沒填代表不設限 |
| 付款條件 | — | 自由文字，預設「完工後三日內付款」，老闆自己改 |
| 備註 | — | 自由文字 |

**明細（至少一行）**

| 欄位 | 必填 | 說明 |
|---|---|---|
| 品名 | ✅ | 自由填 |
| 數量 | ✅ | 可含小數（工時類會用到 1.5 小時），須 > 0 |
| 單價 | ✅ | 整數台幣，須 ≥ 0 |

## 計算

- **小計** ＝ 數量 × 單價（每行）
- **總額** ＝ Σ 小計 —— **唯讀，不接受輸入**。這不是 UI 的貼心，是[架構圖原則 1](架構圖.md#原則每條之後都要變成一個測試) 的兌現方式：總額沒有輸入的地方，就沒有對不起來的一天。
- **剩幾天** ＝ 有效期限 − 今天 —— 查詢時現算，不存欄位、不跑排程。

## 權限

v1 是**單人自己用**，沒有登入，所有端點公開。多人與角色是升級鉤——真的有第二個人要用了才做，做的時候先回架構圖加「人」這一層。

> 誠實標記：這是刻意的取捨，不是漏做。這個 repo 是種子，不是可以直接上線收單的產品。

## 驗收（每條都要能跑出來看）

1. 挑一個客戶、填兩行明細（2×1000、1×500），存檔 → 總額顯示 2500，狀態是 `草擬`，單號長得像 `Q20260814-001`。
2. 改第一行數量成 3 → 總額自己變成 3500，**沒有任何地方可以手動改總額**。
3. 明細一行都沒有就想存 → 被擋下，而且看得懂為什麼。
4. 數量填 0 或負數 → 被擋下。
5. 同一天連開三張 → 流水號 `-001`、`-002`、`-003`，不重複。
6. 有效期限填成昨天 → 詳細頁顯示已過期（狀態**不會**自己變）。

## 施工順序（一次一小塊）

先最薄的能動版本：建立＋看得到總額 → 玩壞它（改數量、刪明細、同時開兩張）→ 把上面六條驗收變成測試 → 最後才修畫面。
