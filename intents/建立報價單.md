# 功能規格書 — 建立報價單

> 模組：報價單／動作：建立報價單（主流程①②）
> 只講「建立報價單」這一個動作。狀態、原則、資料的定義都在[知識架構圖](架構圖.md)——這裡引用、不重抄。

## 這個動作在做什麼

老闆接到詢價，開一張報價單：挑客戶、一行一行填要報什麼、系統把錢算出來，先存成草稿，之後再送出。

## 權限

- **要登入才能開單**（帳號先由開發者手建——照[知識架構圖](架構圖.md)使用者模組）；沒登入呼叫建立相關 API 一律擋下。
- **負責人自動＝登入的人**，不能挑別人（架構圖資料表：負責人＝開單的人）。
- v1 登入的人權限都一樣（誰都能開單）；要分角色時先回架構圖改。

## 驗收（每條都要能跑出來看）

1. 挑一個客戶、填兩行明細（2×1000、1×500），存檔 → 總額顯示 2500，狀態是 `草擬`，單號長得像 `Q20260814-001`。
2. 改第一行數量成 3 → 總額自己變成 3500，**沒有任何地方可以手動改總額**。
3. 明細一行都沒有就想存 → 被擋下，而且看得懂為什麼。
4. 數量填 0 或負數 → 被擋下。
5. 同一天連開三張 → 流水號 `-001`、`-002`、`-003`，不重複。
6. 有效期限填成昨天 → 詳細頁顯示已過期（狀態**不會**自己變）。
7. 未登入呼叫建立端點 → 被擋下（401/導去登入）。
8. 登入 A 帳號開單 → 這張單的負責人顯示 A，且沒有任何地方可以改成別人。

## 施工順序（一次一小塊）

先做「能建立＋看得到總額」的最小版本 → 試極端操作（改數量、刪明細、同時開兩張）→ 把上面的驗收逐條變成自動測試 → 最後才做畫面。

## 對應實作

- API：`POST /api/v1/quotations`（建立）、`GET /api/v1/quotations/{id}`（詳細）、`PUT /api/v1/quotations/{id}`（詳細頁編輯存檔：明細＋有效期限、付款條件、備註）、`PUT /api/v1/quotations/{id}/items`（只換明細）；挑客戶 `GET/POST /api/v1/customers`、挑商品 `GET /api/v1/products`（兩支都分頁）
- 測試：`apps/lean-backend/apps/quotations/tests.py`——驗收 8 條逐條＋原則 1／6／7／8
- 畫面：`apps/lean-admin/src/views/QuotationDetailView.vue`（開新單＝同一頁的建立模式；挑客戶、挑商品用搜尋＋分頁對話框）
