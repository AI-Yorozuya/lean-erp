# 功能規格書 — 轉成訂單

> 模組：訂單／動作：轉單（主流程⑥，跨模組：報價單→訂單）
> 只講「轉單」這一個動作。狀態、原則、資料的定義都在[知識架構圖](架構圖.md)——這裡引用、不重抄。

## 這個動作在做什麼

成交的報價單一鍵轉成訂單開始管交付。**已成交才能轉**（[架構圖原則 5](架構圖.md)）；一張報價轉一張訂單（架構圖・現在不做：拆多張）。

## 行為

- 轉單＝建訂單＋**把報價明細複製成訂單明細**（品名、數量、單價存訂單自己的一份；之後改報價單不會動到訂單）。
- 訂單號 `O`＋日期＋三碼流水，同日連號不重複（做法同報價單號——[架構圖原則 6](架構圖.md)）。
- 訂單欄位：單號、狀態（`待處理` 起）、預計交付日（可空）——照架構圖・資料。
- **轉單後報價單仍可改**（拍板 2026-08-23）：照常留紀錄，但不會動到訂單——報價單記談的過程、訂單記要交付的內容，各存各的。
- **作廢**：`待處理` 的訂單可作廢 → 訂單留一筆作廢紀錄（不真刪）、報價單回 `已成交`（照架構圖狀態機的退路）。

| 預計交付日 | （可不填） |

## 驗收

1. 已成交按轉單 → 出現 `O` 開頭訂單、狀態 `待處理`、明細與報價單當下一致。
2. 草擬／已送出／沒成的單打轉單 API → 被擋，看得懂為什麼。
3. 作廢 `待處理` 訂單 → 訂單留作廢紀錄、報價單回 `已成交`、可再轉一張新訂單。
4. 轉單後改報價明細 → 訂單明細不動。

## 施工順序

訂單＋訂單明細 model → 轉單（複製＋取號）→ 作廢 → 驗收變測試 → 畫面。
