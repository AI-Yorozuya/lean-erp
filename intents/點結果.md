# 功能規格書 — 點結果

> 模組：報價單／動作：點成交／沒成（含點錯改回）（主流程⑤）
> 只講「點成交／沒成」這一個動作。狀態、原則、資料的定義都在[知識架構圖](架構圖.md)——這裡引用、不重抄。

## 這個動作在做什麼

客戶回話了：`已送出` 的單點「成交」或「沒成」；點錯了改回 `已送出`。狀態機照[架構圖・流程](架構圖.md)，這裡不重畫。

## 行為

- 只有 `已送出` 能點結果；`已成交`／`沒成` 只有「點錯改回」一條路。
- 每次點（含改回）都寫修改紀錄（[架構圖原則 4](架構圖.md)：狀態退回也是修改）——用「送出與收回」建好的那套紀錄。
- 沒成不填原因（架構圖・現在不做：失單原因）。

## 驗收

1. 已送出點成交 → `已成交`＋一筆紀錄；點沒成 → `沒成`＋一筆紀錄。
2. 點錯改回 → 回 `已送出`＋一筆「改回」紀錄。
3. 草擬單畫面上沒有點結果的按鈕；直接打 API → 被擋。

## 施工順序

狀態轉移 API（成交／沒成／改回，各帶狀態檢查）→ 驗收變測試 → 詳細頁按鈕。

## 對應實作

- API：`POST /api/v1/quotations/{id}/win`、`/lose`、`/reopen`；狀態轉移表在 `apps/quotations/services.py` 的 `TRANSITIONS`
- 測試：`apps/lean-backend/apps/quotations/tests_result.py`——驗收 3 條
- 畫面：報價單詳細頁表頭「成交／沒成／點錯改回」
- 補的一條守門：已轉成訂單的報價單不能點錯改回，要先作廢訂單（不然報價單回已送出、訂單還在跑，兩邊對不起來）
