# lean-erp — 報價成交切片

一個小生意用的最小系統：**客戶問價 → 開報價單 → 談成轉訂單**。三張表，跑得起來。

這個 repo 同時是一份教材。它不是先寫程式再補文件——**它自己照著「意圖驅動設計」蓋**：先把判斷寫成兩份薄文件（`intents/`），程式再照著文件長出來。你現在看到的順序，就是我們主張的順序。

## 第一次來？

先看 [START.md](START.md) 把環境裝起來（一次性，約半小時）。已經有 Claude Code＋Docker 的人跳過。

## 方法在這一頁

[`docs/意圖驅動設計.html`](docs/意圖驅動設計.html)：意圖收斂 → 架構管理 → 程式開發一頁看完，下半頁是拿著跑的——貼 prompt、照著說、勾著走。這個 repo 的 `intents/` 就是照這一頁做出來的。系統總覽由 `intents/gen-系統總覽.py` 從 `intents/` 的 md 產生。

## 這裡有什麼

```
intents/          ← 知識層：人的判斷（先有這個）
  架構圖.md         整個系統一頁看完：資料·流程·頁面·原則
  建立報價單.md      從架構圖切一塊放大：欄位·計算·權限·驗收
（程式碼隨後）
```

**為什麼文件在前**：程式碼長得回來，判斷猜不回來。AI 可以照著這兩份文件重新生成整個系統；但你腦中「總額不能手打」「已成交才轉訂單」這些決定，一旦沒寫下來就散在幾百句對話裡，AI 每開一個新視窗就重猜一遍。

## 紅線

- **這個 repo 零真實資料**。所有資料都是 seed 出來的假資料，`.env` 永不進 repo。
- 它是種子，不是成品——**跑得起來，但不會剛好是你家的樣子**。要改成你家的，需要的不是這份 code，是收斂與設計的方法。

## 狀態

🚧 知識層先落地，程式碼施工中。
