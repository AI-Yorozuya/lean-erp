# lean-erp — 報價系統

3C 店的業務替公司客戶開報價單，匯出 PDF 傳給客戶；老闆看每月業績。這就是《AI 做出你的第一套商業系統》課程從頭做到尾的那套系統。

這個 repo 同時是一份教材。它自己照著「意圖驅動設計」蓋：先把判斷寫下來（`intents/`），程式再照著長出來。你現在看到的順序，就是課程主張的順序。

## 第一次來？

先看 [START.md](START.md) 把環境裝起來（一次性，約半小時）。已經有 Claude Code＋Docker 的人跳過。

本機預設帳號：`dev / dev1234`（業務 林郁婷，用銷售管理）、`boss / boss1234`（老闆，看業績）。

## 方法在這一頁

[`docs/意圖驅動設計.html`](docs/意圖驅動設計.html)：意圖收斂 → 架構管理 → 程式開發一頁看完，下半頁是拿著跑的——貼 prompt、照著說、勾著走。

## 這裡有什麼

```
intents/                     知識層：人的判斷（先有這個）
  意圖清單.md                  意圖收斂交出的：五件事
  頁面清單.md                  意圖收斂交出的：每種資料的列表頁、詳細頁、互動元件
  原型.html                    意圖收斂交出的：能點的頁面原型
  系統總覽.json                架構管理的正本：資料、關係、頁面、規格、權限、流程、原則、版本
  系統總覽.html                產生器從 json 出的，人看這個；不手改
.claude/skills/system-overview  改系統總覽用的 skill 與產生器（node build.cjs intents/）
apps/lean-backend            Django-Ninja 後端
apps/lean-admin              Vue3 + shadcn-vue 後台
infra/                       本機與正式環境
```

**為什麼文件在前**：程式碼長得回來，判斷猜不回來。「單價照價目表、不能手改」「已送出的報價單不能改」「滿十萬免運」這些決定，沒寫下來就散在幾百句對話裡，AI 每開一個新視窗就重猜一遍。

## 狀態

兩個模組都施工完：

- 銷售管理（業務）：客戶、商品、報價單的列表頁與詳細頁，選取客戶、選取商品兩個對話框；確認建立、匯出 PDF、商品儲存三塊規格。
- 報表分析（老闆）：業績頁，每月報價張數與報價總額，從已送出的報價單算；老闆只能看業績，不能改報價單。

系統總覽的八條驗收與九條原則都有測試守著（測試名就是系統總覽上的程式名）。

## 紅線

- **這個 repo 零真實資料**。所有資料都是 seed 出來的假資料，`.env` 永不進 repo。
- 它是種子，不是成品——**跑得起來，但不會剛好是你家的樣子**。要改成你家的，需要的不是這份 code，是收斂與設計的方法。
