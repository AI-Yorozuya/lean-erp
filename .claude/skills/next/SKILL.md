# /next — 你在哪、接下來做什麼

這個專案照五站走：**意圖（含原型）→ 架構 → 規格 → 施工 → 回頭挑下一塊**。
每站有明確的產出與過關條件；本 skill 的工作是**看檔案判斷你在哪站**，然後帶你走那一站——不代替你做任何判斷。

## 第一步：判斷現在在哪站（照順序檢查，第一個成立的就是）

| 檢查 | 成立 → 你在 |
|---|---|
| `intents/交接包.md` 和 `intents/架構圖.md` 都不存在 | **意圖站** |
| 交接包存在，架構圖不存在（或檔頭沒有「✅ 已簽核」） | **架構站** |
| 架構圖已簽核，但要蓋的那塊在 `intents/` 沒有規格書 | **規格站** |
| 規格書存在，code 還沒蓋完或測試沒全綠 | **施工站** |
| 這塊蓋完、驗收過 | 回架構圖挑下一塊；全部夠用了→上線（`infra/`） |

**出廠範例分岔**：這個 repo 自帶「報價成交切片」的架構圖與規格書（已簽核的範例正本）。第一次打 `/next` 先問一題：

> 照範例蓋報價單系統，還是換成你自己的生意？

- **照範例** → 直接進施工站（範例的架構圖與規格書就是正本）。
- **自己的生意** → 先執行 `cp -r intents intents_範例參考`（範例留著隨時對照），再從意圖站開始。

## 各站怎麼走

### 意圖站
打 `/converge-intent`。三站（聊想法→對流程→點畫面）、兩道閘門，最後把**交接包**寫進 `intents/交接包.md`（意圖清單＋主流程＋東西清單＋現在不做）。

### 架構站
拿交接包長成一張架構圖——**照範例架構圖的形**：四問／資料／流程／頁面／原則／現在不做，六段、一頁。

- 只寫 **AI 猜不到的判斷**——CRUD、分頁、按鈕長怎樣不寫。這份變厚就是警訊。
- 每條原則之後都要能變成一個測試。
- AI 出草稿、人逐段改；**至少改一處才算看過**（全盤接受＝還沒真的讀）。
- 簽核＝需求方看完說「簽」，AI 在檔頭補一行 `> 狀態：✅ 已簽核 YYYY-MM-DD`。

### 規格站
從架構圖挑一塊放大成規格書——**照範例規格書（建立報價單.md）的形**：這一塊在做什麼／欄位／計算／權限／驗收。

- 第一塊怎麼挑：主流程上**最靠近錢的那個動作**。
- 規格從架構圖長出來，不從畫面長出來。
- 一塊一份檔，存 `intents/<動作名>.md`。

### 施工站
對 AI 下單用固定句型：**做哪塊＋規格在哪＋怎麼驗**（例：「做建立報價單，規格照 intents/建立報價單.md，驗收跑它的驗收段」）。紀律：

1. **plan-first**——先看施工計畫、找碴，再動手。
2. **一次一小塊**，做完能跑再進下一塊。
3. **原則變測試**——架構圖每條原則都要有一個測試守著。
4. 改壞就退回（git），敢改的底氣是隨時退得回。

**驗收＝三件都過**：規格書驗收段逐條過＋原則測試全綠＋照主流程把畫面從頭走一遍。

### 完成一塊之後
回架構圖：挑下一塊出規格書；或「現在不做」清單裡有東西真的痛了→**先改圖，再施工**。要給別人用了→上線（`infra/`，照 `infra/README`）。

## 紅線

- **判斷是人的**：架構圖與規格書的每個決定都要人點頭；AI 只出草稿與選項（附代價）。
- **不跳站**：沒簽架構圖不出規格書，沒規格書不施工。
- **新需求不直接改 code**：先問它長在架構圖哪裡（新的東西？新狀態？撞到哪條原則？），改完圖再切一塊施工。

## 回報格式

每次 `/next` 開場先報三行，再開始帶站：

```
你在：施工站（建立報價單）
上一站交付：intents/建立報價單.md ✅
這一站目標：後端 API 蓋好、原則 1/5 的測試綠
```
