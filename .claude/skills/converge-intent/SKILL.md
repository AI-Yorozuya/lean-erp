# Converge Intent

把人腦中的散裝描述變成一份可共同校正的交接 brief。這是產品開發流程五站中的**前兩站（意圖、原型）**——知識架構圖、功能規格書與製作計畫都在閘門之後；不要取代它們。

方法：**兩個迴圈、兩道閘門、一個袋**。

## 守則

- **先意圖，後方案**：聽到「我要一個 XX」先問「要它是為了什麼」，追到答案出現決定或後果就停。
- 先回述，後提案。只有使用者說過或可查證的內容是事實。
- 每個主張標成 🟢事實、🟡推論／建議、或 🔴問題；🔴 不得補成答案。
- 操作畫面原型只用來討論故事與後果；能點，但不做精修 UI／影片／文件。
- 不替使用者拍板領域規則；一次只問最能解鎖下一步的問題。**不准要求使用者自己拆塊**——拆塊是你的工作，他只負責挑或改。
- 不直接開始實作。完成本 skill 後，要交給架構站或製作流程。

## 迴圈契約——迴圈必須真的轉起來

- **每一輪都以「回述＋至多一問」收尾**——不准一次倒完所有問題，也不准悶頭產出長文。使用者回了，才算下一輪。
- **閘門未過就留在圈內**：意圖迴圈出口＝四問答得出來＋使用者能用自己的話複述（複述不出＝續圈，不是加字數）；原型迴圈出口＝主流程走得完＋核心物件連續兩輪不變＋剩餘 🔴 全數值性。
- **過門由你主動宣告**，不等使用者喊停；使用者可否決，否決＝續圈。
- 收斂儀表：一次一題、事實自查·決策問人、每題附建議答、決策題附候選（必含「先不決定」）、🔴 分流（結構性才佔問題名額，數值性入袋不唸）、開關比、回述遞減。
- 兩目的相撞時收斂成「哪個先讓步」的單選；中途新增目的先明列翻掉哪些結論，逐條改、不重來。讓步方與砍掉的訴求進「現在不做」清單。
- **🔴 行內嵌**：凡已有 brief／故事板／原型稿，🔴 除了列清單，同時就地嵌 `[🔴: 具體問題]` 在缺口的確切位置——清單管排程（本輪問哪題），行內管位置（答案回填處）；同一缺口兩處同源，回填時一起銷。

## 迴圈一：意圖（收料 ⇄ 回述校正）

輸入不限形式：口述、隨意自然語言、meeting 錄音逐字稿、會議記錄、雜訊筆記皆可。對照**意圖四問**萃取：①給誰用？②用來做什麼？③做完會得到什麼？（答**利益**不答產出物規格；答案出現名詞——表／頁／報表——就追問「有了它你會怎樣」，到出現動詞或後果為止）④一條原則：什麼絕對不能發生？（N 種子）。四問是閘門 1 的檢核：缺的留白＝🔴，不猜。

**第四問的判準**：答案必須是「判得出有沒有發生」的事件——比對得出來、擋得住、寫得成測試（它後面會長成 N 不變量與一條驗收）。感受型的願望（「不能得罪客人」）不算：判不出也擋不住；答不出就留白進 🔴，不拿感受充數。

第二輪起：🟢 只列本輪新增與變更；🔴 只列結構性。**提案必附代價**（解什麼＋傷什麼）。**類比錨起手**：對焦初期可拋一問「這像你現有的哪個功能／流程，或別人家的哪個東西？」——一個類比一次帶出一串核心物件×動作；答不出就放掉，不硬套。

**閘門 1 產出＝意圖清單**（四問的答案，一張卡）。

## 迴圈二：原型（推主流程 ⇄ 點畫面）

從意圖清單推一條主流程：`起點 → 動作 → 可見結果`，請使用者說像／不像；再把主流程做成**操作畫面原型**（按鈕能走完＝使用者驗證故事的方式），收出**不可猜的核心物件×動作**。**點名不解答**：某個核心物件「怎麼存」若是資料表長相的分水嶺，這裡只點名，答案帶進架構站問（數量是警戒線不是規格：多數小系統 3–7 個，明顯更多先檢查是不是把欄位當成物）。不展開欄位、計算、權限或完整狀態機——那些留給架構站與功能規格書。

**排序題（「先做哪塊」）在這裡問**——主流程長出來才有塊可指，意圖迴圈裡不問。問法用事實題：「你上一次實際做這件事，從頭走一遍給我看」——每次都做的是主幹，偶爾才做的進「現在不做」。

**閘門 2 產出＝主流程＋核心物件×動作清單**（原型＝頁面層的參考，規格從架構圖長）。未拍板數值不在這裡解：會改變「要不要做／怎麼做」的＝結構性，照決策題處理；只改設定值的直接入袋。

## 交接

交接由閘門 2 觸發（主動宣告，不等使用者喊停）。回報下列其中一種結果：

- **未收斂**：保留 GAP，帶著下一個問題續圈。
- **可進架構站**：帶交接包進架構站收知識架構圖（有需求方→六站訪談）；從零系統可接 `intent-to-rules`。
- **可進製作**：交給對應領域的腳本、SOP、活動計畫或開發切片；先附回溯到本 brief 的成功條件與底線。

**交接包五件**（每件＝知識架構圖某一層的種子）：①意圖清單（→目的與原則）②主流程（→流程層）③核心物件×動作清單（→資料層）④操作畫面原型（→頁面層的參考）⑤「現在不做」清單——待確認（照資料模型・原則・流程分好）＋park（先不決定）＋割捨（不在本次範圍＋一句為什麼，防下游範圍蔓延、也是下輪收斂起點）。

## 輸出排版——畫面必須簡潔易懂

所有對話產出固定用下列模板，**寧短勿長**：排版的職責是讓使用者 10 秒內看懂「現在在哪、要回什麼」。禁止長段落敘述、禁止每輪重貼全量已知。

每輪回述：

```markdown
## 這一輪
- 🟢 新增／變更：（只列本輪）
- 🟡 推論／建議：（附代價：解什麼＋傷什麼）
- 🔴 還不知道：（只列結構性；另 N 條數值已入袋）

**本輪只回這題** → 一題，附 2–4 個候選（各帶代價，含「先不決定」）
```

意圖清單（閘門 1 過門時）：

```markdown
# 意圖清單
- **給誰用**：…
- **用來做什麼**：…
- **做完會得到什麼**：…
- **絕不能發生**：…

你能用自己的話講一遍嗎？講不順的那格我們再修。
```

交接包（閘門 2 過門時）：五件各一段、每段不超過五行；「現在不做」分三小節（待確認／先不決定／本次不做）。

## 最小輸出

過閘門 2 後，把交接包寫進 `intents/意圖清單.md`（四問＋主流程＋核心物件×動作＋「現在不做」三小節），交還 `/next` 進架構站。對話中輸出：

1. 意圖清單：四問的答案。
2. 一條主流程（故事板）。
3. 核心物件×動作清單。
4. 「現在不做」清單。
5. 下一個問題或明確交接點。
