# Converge Intent

把人腦中的散裝描述變成一份可共同校正的意圖定稿。這是產品開發流程五站中的**前兩站（意圖、原型）**——知識架構圖、功能規格書都在閘門之後，不要取代它們。

> 本檔為交付副本（自足）；正本住 ai-yorozuya `jarvis/skills/converge-intent/`，改正本→同步這裡。

## 全景

**兩個迴圈、兩道閘門、一個袋**；進度顯示三站，**名稱一律照意圖驅動設計一頁圖**，不另造詞：

| 站 | 是什麼 | 過門條件 | 過門產出（正名） |
|---|---|---|---|
| 意圖迴圈（1/3） | 講 ⇄ 回述校正 | 四問每格過線＋他看清單點頭 | **意圖清單**（一張卡，之後不再長大） |
| 原型迴圈（2/3） | 推主流程 ⇄ 點畫面原型 | 主流程走得完＋物件連續兩輪不變＋結構題清零（依檔位） | **主流程＋核心物件清單**＋袋收口 → 四件合訂＝**意圖定稿** |
| 領域知識（3/3） | 架構站——**本 skill 之外**，出口 | — | 架構圖（下一站簽核的事） |

「暫不實作」袋全程收（隨口的以後想要、數值題、砍掉的訴求），閘門 2 收口。

## 開場（第一輪固定三動作）

1. **問強度**（表單一題）：速寫（練習／demo）／標準（自己的生意，**預設推薦**）／嚴格（收錢、簽約、上線）＋固定末項「這題怪怪的」。
2. **報整場的形**：「三站：先聊清楚要做什麼（意圖迴圈，通常 2–4 輪）→ 再一起把流程和畫面對一遍（原型迴圈，通常 2–3 輪）→ 最後整理成設計圖給你簽（領域知識）。你隨時可以喊停。」
3. **請他開講**：想到什麼講什麼——口述、逐字稿、會議記錄、雜訊筆記都收。

## 互動規則（每一輪都適用）

- 每輪固定形：**儀表行 → 回述 → 至多一問**。使用者回了才算下一輪；不准一次倒完所有問題、不准悶頭產長文。
- **有結構化提問工具（如 AskUserQuestion）就用表單**：每題最多 4 個選項、可複選用 multiSelect；**固定末兩項＝「換個問法」＋「這題怪怪的」**——換個問法＝題目沒壞但他想聽別種說法或沒聽懂（換個角度重問，不登記）；怪怪的＝題目本身有病（走爛題登記）。扣掉末兩項，實質選項每題最多 2 個，不夠就拆成多題並列。**進度行放進表單前導文**（使用者盯的是表單，表單外的進度等於沒有）。沒有工具→文字編號選項。
- **確認也是題**：清單點頭、過門、總確認一律用表單（「都對，過門」／「有要改的」＋固定末兩項），不出開放式「點頭嗎」「哪裡不對」散文——選了「有要改的」才逐項問。**確認＝單一複選題**：**長產出的確認：先寫成 md 草稿檔、把檔案開給使用者看，表單選項只放標題**（首項固定「以上皆對」；label＝件名、description＝一行摘要）——別把全文塞表單（description／preview 都擠）。勾完把「✅ 已確認」寫回檔頭；勾了要改的，改檔再確認。短確認（單格）仍可直接表單。其餘規則：勾了就是對，沒勾的用自由輸入直接打怎麼改，全部勾完就進下一站。**對使用者顯示的文字不用「＝」**——那是我們的符號，不是人話（寫「全部勾完就進下一站」，不寫「全勾＝過門」）。一題最多 4 格，超過才拆第二題。確認題不掛固定末兩項（自由輸入就是逃生口）。「看上面那張」永遠不算數——內容必須在表單選項裡。
- **回答成本上限＝挑一個**：每題都要能用選項或點頭答完。要他去數、去翻、去寫的題不出——那筆資料之後從系統資料自己算，或降級成「重要／不重要」判斷題。
- 決策題附 2–4 個候選、各帶代價（解什麼＋傷什麼）、必含「先不決定」（入袋）。不出裸問句；**不准叫使用者自己拆塊**——拆塊是你的工作，他只負責挑或改。
- **先意圖，後方案**：聽到「我要一個 XX」→「要它是為了什麼？」，追到答案出現決定或後果就停。
- **事實題六關**（出手前逐關過）：①回答成本上限＝挑一個②一題一事件、一個時間尺度（跟進＝天週、回查＝月年，拆開問）③先過濾再深挖（「有沒有發生過X？」——「沒有」也是黃金答案）④問那件事的三要素（情境／做了什麼／後果），不問「隔多久」「多常」⑤能選就不問開放題⑥「為什麼」至多追兩層（答案滑到理念＝到頂，收線）。
- **對自建者不出「證明你的痛」的功課題**——錨定用寄生的：他主動講到的真事直接收錨；看流程時順口邀他對照最近一件真事（零成本邀請，不是作業）。
- **「這題怪怪的」被選＝題目有病**：原題不追問 → 自診破了哪關 → 換問法或跳過（跳過合法）→ 記一行進本資料夾 `爛題登記.md`（日期／原題／破哪關／改成什麼）。**出題前先讀登記簿，同型錯不再犯。**
- 🔴 分流：**結構性**（答案會改變核心物件、主流程或責任線）才佔問題名額；數值性直接入袋，回述一行帶過。**開關比**：本輪關掉的題 < 新開的題 → 下輪禁提新問，先出收斂稿釘住已知。**回述遞減**：只列本輪新增與變更，一輪比一輪短。
- **🔴 行內嵌**：已有草稿／流程稿時，🔴 除了列清單也就地嵌 `[🔴: 具體問題]` 在缺口位置，回填時兩處一起銷。
- 目的相撞 → 收斂成「哪個先讓步」的單選；中途新增目的 → 先明列翻掉哪些結論，逐條改、不重來；讓步方進袋。

## 儀表（兩面）

- **機器面**（AI 每輪內部記錄、判過門用，不上桌）：意圖迴圈＝格 x/4・🔴剩 z 結構・新項率；原型迴圈＝流程 k/n 步像・Δ物件・🔴剩 z（w 數值入袋）・穩定 s/2 輪。
- **人面**（唯一顯示）＝兩行：第一行**站名頭**`意圖迴圈｜▓▓░░｜還缺：得到什麼、絕不能發生`——**bar 後只寫「還缺什麼／下一步動作」，不准重述 bar 已顯示的狀態**（「4 題答了 2 題」＝bar 已經說了，寫出來是廢話；滿格時直接寫下一步動作）。**progress bar 必放、不放輪數**（bar 在，輪數就是雜訊）：bar 格數＝站內可知分母（意圖迴圈＝4 題、推主流程＝流程步數、點畫面原型＝封口後剩餘題數；分母還不可知時暫以「第 n 輪」代替 bar）——一眼看得出差幾格——站名＋括號＝**該迴圈的累加輪數**`（第 3 輪）`：每輪 +1，**不帶分母、不做預估**（總輪數不可知，預估分母只會跟著分子跑）；「還要多久」由後面的白話句承擔（還缺什麼、預計再聊幾輪可在句子裡估）；第二行**路線圖**`意圖迴圈 → 原型迴圈 → 領域知識`（完成打 ✓、進行中加粗）。表單前導文空間有限時只放第一行。**「格」「卡」「錨」等內部詞不上桌**——卡＝「這張清單」、格＝「題」。
- 規則：**分母只准用可知的數**（四問＝4 題、主流程步數、封口後的剩餘件數）；輪數與問題總數禁當分母；**禁報「完成 xx%」**。儀表每一輪都要有變化——連兩輪全同＝發散警訊，自查。
- 機器面已趨零又跳動＝警訊：回頭查，不硬停。

## 強度三檔（開場設定、中途可換）

| | 速寫 | 標準（預設） | 嚴格 |
|---|---|---|---|
| 四問 | 有字即可 | 每格過線 | 每格過線 |
| 錨定 | 免 | 寄生（流程對照真實案例） | 每格明確錨定（對外訪談／接案用） |
| 飽和 | 免 | 新項率連續 2 輪 ≤5% | 連續 3 輪 0 新項 |
| 穩定 | Δ=0 × 1 輪 | Δ=0 × 2 輪 | Δ=0 × 2 輪＋每條原則附反例 |
| 結構性 🔴 | 可入袋帶走 | 清零 | 清零＋決策留痕 |

換檔：**升檔 → 立刻列缺口清單**；**降檔 → 記一筆進袋**（誰決定的、為什麼）。

## 站 1 意圖迴圈（講 ⇄ 回述校正）

對照**意圖四問**萃取，缺的留白＝🔴，不猜：

1. **給誰用？**——過線＝說得出誰會開、誰會看（角色即可，不用 persona）。
2. **用來做什麼？**——過線＝有動詞、有對象。
3. **做完會得到什麼？**——答**利益**不答產出物規格；答案出現名詞（表／頁／報表）→ 追問「有了它你會怎樣」，到出現動詞或後果為止。
4. **什麼絕對不能發生？**——過線＝判得出有沒有發生、寫得成測試（它會長成不變量與驗收）；感受型願望（「不能得罪客人」）不算，答不出留白進 🔴。

**類比錨起手**（可選）：「這像你現有的哪個流程、或別人家的哪個東西？」——一個類比帶出一串物件×動作；答不出就放掉。

**閘門 1**＝每格過線＋他看卡點頭（哪格不對就改，改到點頭；不要求複述——不考客人）。過門亮出**意圖清單**卡。

## 站 2 原型迴圈・第一拍：推主流程

從意圖清單推一條主流程 `起點 → 動作 → 可見結果`，用表格呈現（每步：他做什麼／他看到什麼）。**每步描述要具體到「他按什麼、畫面回什麼」**——不准用黑箱動詞包（「當場建一筆」沒講建什麼欄位、建去哪，這種步驟判不了像不像；要寫成「填名字＋電話存成新客戶」這種看得見的動作）。

- 確認＝**複選表單**：每步一個勾選項（勾「不像」的）＋「這幾步都像」＋「這題怪怪的」；步驟多就分組成多題。勾了哪步，只追問那一步。
- **寄生錨定**（零成本邀請）：「順手拿最近真的一件，在腦中照著走——哪步不像點出來就好。」
- **終點題（必問）**：主流程最後一步確認完，問一次「然後呢——系統到這裡交棒給人工，還是後面還有？」（例：成交之後接不接訂單管到交付）。終點是拍板不是預設；不問，下游整段需求就靜靜消失。
- **反悔題（必問）**：主流程推完，把**每個狀態變化**（送出、標成交／沒成、刪除…）逐一挑出來，問一題「點錯了怎麼辦」——候選固定三型：①可直接改回（留紀錄）②限時收回（幾分鐘內可 undo）③不能退（動作前加確認框）。回復規則是結構性問題（動狀態機與留痕），不問＝只驗了正常走法，交付後第一次點錯就炸。
- **排序（先做哪塊）在這站問**：主流程出來才有塊可指。**由你提案**哪幾步是主幹、哪幾步可進「暫不實作」，附代價，他點頭或改。

過門亮出**主流程**。

## 站 2 原型迴圈・第二拍：點畫面原型

- 把主流程做成**能點的操作畫面原型**。**repo 有現成前端骨架（如 lean-admin）就直接在裡面開 view**：假資料寫死在 view、不碰 API 不碰資料庫（碰了＝施工，留在簽架構圖後）；簽圖前這些 view 隨時可整檔重寫——可丟紀律不因為寫成 Vue 就失效。確認完的原型 view 之後接上 API 就是成品的種子。沒有前端骨架才退回單檔 HTML＋假資料；再不行退化成逐屏文字稿確認。**原型的皮照目標 repo 的既有版型**（lean-stack 系＝lean-admin 後台版型，動手前先載 admin-ui skill 參照）——像不像判的是「他未來真的會看到的樣子」，不是我的臨場美術。**確認一輪一屏**：一次只給一個畫面、一題確認，點完這屏才換下一屏——不准一張表單問三個頁面。
- 收出**不可猜的核心物件×動作**，並做**物件×頁面對照**：每個物件問一次「要自己的列表／詳細頁，還是寄生在別的畫面（如挑選對話框）就夠？」——沒對照，物件會靜靜漏頁（判例：客戶只活在挑選框裡，管理頁沒人問）。寄生也是合法答案，記進核心物件清單。點名不解答：「怎麼存」是資料表分水嶺的只點名、帶進架構站（警戒線：多數小系統 3–7 個物件，明顯更多先檢查是不是把欄位當成物）。不展開欄位、計算、權限、完整狀態機。
- 清結構題（表單／候選形式）；數值題入袋。
- **閘門 2**（依檔位）＝主流程走得完＋核心物件連續兩輪不變＋結構性 🔴 清零（只剩數值）。**由你主動宣告**，他可否決，否決＝續圈。

## 交接（過閘門 2）

三種結果：**未收斂**（保留 GAP 續圈）／**可進架構站**（意圖定稿→知識架構圖；從零系統可接 `intent-to-rules`）／**可進製作**（交對應領域流程，附回溯本包的成功條件與底線）。

**意圖定稿＝四件合訂**（每件＝知識架構圖某一層的種子）：①意圖清單（→目的與原則）②主流程（→流程層）③核心物件×動作清單（→資料層）④「暫不實作」清單——只收**決定不做的**（先不決定、本次不做，各附一句為什麼→範圍界線）；⑤「待回答」清單——**還沒答的問題**（畫設計圖前要補答）。兩者不准混：不做是決定，沒答是欠帳。原型＝頁面層**參考**，規格從架構圖長。**整包叫意圖定稿，不准叫意圖清單。**

**lean-stack 系 repo：把意圖定稿寫成 `intents/意圖定稿.md`，然後交還 `/next` 進架構站。** 其他環境預設對話輸出。

## 輸出模板

每輪回述：

```markdown
意圖迴圈（1/3）｜4 題答了 2 題——還缺「做完會得到什麼」「絕不能發生什麼」，大概再聊 2 輪
**意圖迴圈** → 原型迴圈 → 領域知識

## 這一輪
- 🟢 新增／變更：（只列本輪）
- 🟡 建議：（附代價：解什麼＋傷什麼）
- 🔴 還不知道：（只列結構性；另 N 條數值已入袋）

**本輪只回這題** →（表單，或 2–4 個候選各帶代價、含「先不決定」）
```

意圖清單（閘門 1 過門時）：

```markdown
# 意圖清單
- **給誰用**：…
- **用來做什麼**：…
- **做完會得到什麼**：…
- **絕不能發生**：…

（接確認表單：都對，過門／有要改的／換個問法／這題怪怪的）
```

意圖定稿（閘門 2 過門時）：五件各一段、每段不超過五行（意圖清單／主流程／核心物件清單／暫不實作／待回答）。
