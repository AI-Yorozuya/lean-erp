# Converge Intent

把人腦中的散裝描述變成三樣可共同校正的清單（意圖清單、資料清單、頁面清單）＋一個能點的頁面原型。這是意圖驅動設計三站中的**第一站（意圖收斂：意圖迴圈＋原型迴圈）**——系統總覽在收斂完成之後，是架構管理的事，不要取代它。

> 本檔為交付副本（自足）；正本住 ai-yorozuya `jarvis/skills/converge-intent/`，改正本→同步這裡。

## 全景

**兩個迴圈、兩次交接、一個袋**；進度顯示三站，**名稱一律照意圖驅動設計一頁圖**，不另造詞：

| 站 | 是什麼 | 交接條件 | 交接產出（正名） |
|---|---|---|---|
| 意圖迴圈（1/3） | 訪談對話 ⇄ 回述校正 | 五件事每件答得出來＋他看清單點頭 | **意圖清單**（五格表，之後不再長大） |
| 原型迴圈（2/3） | 做頁面原型 ⇄ 找齊頁面與互動元件（走一遍流程） | 主流程走得完且頁面清單填滿＋資料連續兩輪不變＋結構題清零（依檔位）＝收斂完成 | **資料清單＋頁面清單＋頁面原型**＋袋收口 → 三樣＝**意圖定稿** |
| 領域知識（3/3） | 架構管理——**本 skill 之外**，出口 | — | 系統總覽（下一站拍板的事） |

「暫不實作」袋全程收（隨口的以後想要、數值題、砍掉的訴求），收斂完成時收口。

## 開場（第一輪固定三動作）

1. **問強度**（表單一題）：速寫（練習／demo）／標準（自己的生意，**預設推薦**）／嚴格（收錢、簽約、上線）＋固定末項「這題怪怪的」。
2. **報整場的形**：「三站：先聊清楚要做什麼（意圖迴圈，通常 2–4 輪；主流程圖在這裡亮）→ 再一起把畫面做出來、走一遍流程找齊頁面（原型迴圈，通常 2–3 輪）→ 最後整理成系統總覽給你拍板（領域知識）。你隨時可以喊停。」
3. **請他開講**：想到什麼講什麼——口述、逐字稿、會議記錄、雜訊筆記都收。

若開場前已有前置討論（同場閒聊、舊筆記、先前的設計對話），把裡面的傾向性取捨列成 🟡 清單先亮一輪重確認——**閒聊＝推論，不是拍板**；沒逐項勾過的取捨照樣要進正式流程。

## 互動規則（每一輪都適用）

**節奏**

- 每輪固定形：**儀表行 → 回述 → 至多一問**。使用者回了才算下一輪；不准一次倒完所有問題、不准悶頭產長文。
- 🔴 分流：**結構性**（答案會改變資料、主流程或責任線）才佔問題名額；數值性直接入袋，回述一行帶過。**開關比**：本輪關掉的題 < 新開的題 → 下輪禁提新問，先出收斂稿釘住已知。**回述遞減**：只列本輪新增與變更，一輪比一輪短。
- **🔴 行內嵌**：已有草稿／流程稿時，🔴 除了列清單也就地嵌 `[🔴: 具體問題]` 在缺口位置，回填時兩處一起銷。
- 目的相撞 → 收斂成「哪個先讓步」的單選；中途新增目的 → 先明列翻掉哪些結論，逐條改、不重來；讓步方進袋。

**出題**

- **有結構化提問工具（如 AskUserQuestion）就用表單**：每題最多 4 個選項、可複選用 multiSelect；**固定末兩項＝「換個問法」＋「這題怪怪的」**——換個問法＝題目沒壞但他想聽別種說法或沒聽懂（換個角度重問，不登記）；怪怪的＝題目本身有病（走爛題登記）。扣掉末兩項，實質選項每題最多 2 個，不夠就拆成多題並列。**進度行放進表單前導文**（使用者盯的是表單，表單外的進度等於沒有）。沒有工具→文字編號選項。
- **回答成本上限＝挑一個**：每題都要能用選項或點頭答完。要他去數、去翻、去寫的題不出——那筆資料之後從系統資料自己算，或降級成「重要／不重要」判斷題。
- 決策題附 2–4 個候選、各帶代價（解什麼＋傷什麼）、必含「先不決定」（入袋）。不出裸問句；**不准叫使用者自己拆解**——拆解是你的工作，他只負責挑或改。
- **先情境，後方案**：聽到「我要一個 XX」→「現在沒有它，這件事是怎麼做的？」；沒有現況就請他假想一次使用，講到拿到東西為止。
- **事實題六關**（出手前逐關過）：①回答成本上限＝挑一個②一題一事件、一個時間尺度（跟進＝天週、回查＝月年，拆開問）③先過濾再深挖（「有沒有發生過X？」——「沒有」也是黃金答案）④問那件事的三要素（情境／做了什麼／後果），不問「隔多久」「多常」⑤能選就不問開放題⑥「為什麼」至多追兩層（答案滑到理念＝到頂，收線）。
- **對自建者不出「證明你的痛」的功課題**——錨定用寄生的：他主動講到的真事直接收錨；看流程時順口邀他對照最近一件真事（零成本邀請，不是作業）。
- **「這題怪怪的」被選＝題目有病**：原題不追問 → 自診破了哪關 → 換問法或跳過（跳過合法）→ 記一行進本資料夾 `爛題登記.md`（日期／原題／破哪關／改成什麼）。**出題前先讀登記簿，同型錯不再犯。**

**確認與拍板**

- **確認也是題**：清單點頭、過門、總確認一律用表單（「都對，過門」／「有要改的」＋固定末兩項），不出開放式「點頭嗎」「哪裡不對」散文——選了「有要改的」才逐項問。**確認＝單一複選題**：**長產出的確認：先寫成 md 草稿檔、把檔案開給使用者看，表單選項只放標題**（首項固定「以上皆對」；label＝件名、description＝一行摘要）。**題目＝一句人話問句**（「這張設計圖畫得對嗎？」），勾法不寫進題目——選項自明，操作說明塞題目＝沒人看得懂——別把全文塞表單（description／preview 都擠）。勾完把「✅ 已確認」寫回檔頭；勾了要改的，改檔再確認。短確認（單格）仍可直接表單。其餘規則：勾了就是對，沒勾的用自由輸入直接打怎麼改，全部勾完就進下一站。**對使用者顯示的文字不用「＝」**——那是我們的符號，不是人話（寫「全部勾完就進下一站」，不寫「全勾＝過門」）。一題最多 4 格，超過才拆第二題。確認題不掛固定末兩項（自由輸入就是逃生口）。「看上面那張」永遠不算數——內容必須在表單選項裡。
- **範圍決定逐項勾**：總確認時「暫不實作」每項一格（label＝項目、description＝一句為什麼不做），不併成一格吃掉；沒勾到的項回「待回答」。閒聊階段談出的取捨也一樣——沒在正式確認裡逐項勾過，就不算定。
- **沒選＝沒答，不是拍板**：使用者跳過、答「沒偏好」、或表單被收掉的題，一律進「待回答」——**不准落進「暫不實作」**（那裡只收明確勾選的決定）。判例：「客戶要不要管理頁」答 No preference，被當成「不做」寫進暫不實作，又併在一格裡被「以上皆對」帶過——事後使用者驚訝「為啥沒有客戶列表」。

**誠實**

- **說「記死」就要真的寫**：對使用者宣告「方法已記死／已修 skill」的每一條，當場寫進正本並回報檔案路徑；沒寫進檔＝沒記，宣稱不算（判例：架構站「狀態圖必附、泳道不畫」口頭記死，全 repo 找不到那條規則）。

## 圖的紀律（本 skill 所有給人看的圖適用）

正本＝[diagramming](../diagramming/SKILL.md)（動筆前三問／何時亮圖／怎麼畫／出手前品質閘——mermaid 語法 parse 必過、渲染結果自己看過才交，各至多 2 輪）。本 skill 屬**人面收斂場景**：顏色編類別、不編順序，一張圖 2–3 色（紫＝主流程、綠＝下游單據、灰＝旁支／收尾）。就地硬線兩條：

- **全貌先行**：流程先有一張整條的圖，局部確認錨在圖上；**只給表格＝沒交**。圖管全貌理解、表單管逐步拍板，互不取代（「看上面那張不算數」管的是確認題選項要自足，不是禁止亮圖）。
- **圖永遠是當前版**：改了哪步，圖改完重亮一次再確認——不讓他對著過期的全貌點頭。

## 儀表（兩面）

- **機器面**（AI 每輪內部記錄、判過門用，不上桌）：意圖迴圈＝格 x/5・🔴剩 z 結構・新項率；意圖迴圈另記流程 k/n 步像；原型迴圈＝Δ資料・頁面清單缺 m 頁・🔴剩 z（w 數值入袋）・穩定 s/2 輪。
- **人面**（唯一顯示）＝兩行：第一行**站名頭**`意圖迴圈｜▓▓▓░░｜還缺：特殊規則、一定不能錯`——**bar 後只寫「還缺什麼／下一步動作」，不准重述 bar 已顯示的狀態**（「5 題答了 3 題」＝bar 已經說了，寫出來是廢話；滿格時直接寫下一步動作）。**progress bar 必放、不放輪數**（bar 在，輪數就是雜訊）：bar 格數＝站內可知分母（意圖迴圈＝5 題、主流程圖確認＝流程步數、原型迴圈＝頁面清單缺幾頁；分母還不可知時暫以「第 n 輪」代替 bar）——一眼看得出差幾格——站名＋括號＝**該迴圈的累加輪數**`（第 3 輪）`：每輪 +1，**不帶分母、不做預估**（總輪數不可知，預估分母只會跟著分子跑）；「還要多久」由後面的白話句承擔（還缺什麼、預計再聊幾輪可在句子裡估）；第二行**路線圖**`意圖迴圈 → 原型迴圈 → 領域知識`（完成打 ✓、進行中加粗）。表單前導文空間有限時只放第一行。**「格」「卡」「錨」「寄生」等內部詞不上桌**——卡＝「這張清單」、格＝「題」、寄生＝「顯示於／附在」。
- 規則：**分母只准用可知的數**（五件事＝5 題、主流程步數、頁面清單缺幾頁）；輪數與問題總數禁當分母；**禁報「完成 xx%」**。儀表每一輪都要有變化——連兩輪全同＝發散警訊，自查。
- 機器面已趨零又跳動＝警訊：回頭查，不硬停。

## 站 1 意圖迴圈（講 ⇄ 回述校正）

對照**五件事**萃取，每件都問一次具體的事（問事件不問目的），缺的留白＝🔴，不猜：

1. **誰在做（做給誰）？**——過線＝說得出誰會開、誰會看（角色即可，不用 persona）。
2. **怎麼做？**——有人在做就照上一次從頭到尾怎麼發生的講；還沒有就假想一次使用從頭講到尾。過線＝有動詞、有對象、有順序。
3. **交出什麼？**——做完手上多了什麼。過線＝說得出一個看得見的東西或狀態（一張單、一筆紀錄、一個通知）；「比較方便」這種感受不算。
4. **有什麼特殊規則？**——條件、例外。過線＝每條講得出「什麼情況下」；沒有就明寫「無」。
5. **什麼一定不能錯？**——上次出過什麼錯就講那次；沒有現況就講什麼結果會讓它白做。過線＝判得出有沒有發生、寫得成測試（它會長成原則與驗收）；感受型願望（「不能得罪客人」）不算，答不出留白進 🔴。

目的與紅線不直接問：由你從第五件歸納，填進意圖清單第五格。

**類比錨起手**（可選）：「這像你現有的哪個流程、或別人家的哪個東西？」——一個類比帶出一串物件×動作；答不出就放掉。

**交出意圖清單**＝五件每件過線＋他看卡點頭（哪格不對就改，改到點頭；不要求複述——不考客人）。亮出**意圖清單**（五格表），換原型迴圈。

## 站 1 意圖迴圈・回述裡的主流程圖（從「怎麼做」長出來，不是原型迴圈的一拍）

從五件事的「怎麼做」推一條主流程 `起點 → 動作 → 可見結果`（課程定義 2026-09-17：狀態、交接由 AI 從「怎麼做、交出什麼」推出來標灰、你拍板；原型只找頁面與互動元件，不找流程）。**先亮圖，再談步**：先畫**一張主流程圖**（起點→每步→終點，狀態變化標成節點）渲染到他眼前，畫法照〈圖的紀律〉；**只給表格沒給圖＝這拍沒交**（判例：跑了一整輪收斂，使用者從頭到尾沒看過一張主流程圖，只被局部表單追著跑）。逐步確認的內容用表格展開（每步：他做什麼／他看到什麼）。**每步描述要具體到「他按什麼、畫面回什麼」**——不准用黑箱動詞包（「當場建一筆」沒講建什麼欄位、建去哪，這種步驟判不了像不像；要寫成「填名字＋電話存成新客戶」這種看得見的動作）。

- 確認＝**複選表單**：每步一個勾選項（勾「不像」的）＋「這幾步都像」＋「這題怪怪的」；步驟多就分組成多題。勾了哪步，只追問那一步；改了哪步，圖照〈圖的紀律〉重亮。
- **寄生錨定**（零成本邀請）：「順手拿最近真的一件，在腦中照著走——哪步不像點出來就好。」
- **終點題（必問）**：主流程最後一步確認完，問一次「然後呢——系統到這裡交棒給人工，還是後面還有？」（例：成交之後接不接訂單管到交付）。終點是拍板不是預設；不問，下游整段需求就靜靜消失。
- **反悔標記（不在這站問）**：主流程推完，把每個狀態變化（送出、標成交／沒成、轉訂單…）記進「待回答」——**回復規則在架構管理拍板**：起草設計圖時直接把預設退路畫進狀態流（改回上一狀態＋留紀錄），他看圖改，不憑空答。理由＝反悔是狀態機的逆向邊，本來就是系統總覽流程頁的內容；在意圖站問＝打斷節奏（判例：反悔題表單連續被收掉）。
- **排序（先做哪段）在這站問**：主流程出來才有段可指。**由你提案**哪幾步是主幹、哪幾步可進「暫不實作」，附代價，他點頭或改。

主流程圖確認完，跟五件事一起交出**意圖清單**（圖＋步驟表附在清單後，圖在前）。

## 站 2 原型迴圈：做頁面原型 ⇄ 找齊頁面與互動元件（走一遍流程）

- **先列資料，再加動作**：先做一個只列這件事該有的資料、不加按鈕的極簡畫面；他一筆一筆看資料從哪裡來、能做什麼，你再把按鈕加上去——這就是**能點的頁面原型**。**repo 有現成前端骨架（如 lean-admin）就直接在裡面開 view**：假資料寫死在 view、不碰 API 不碰資料庫（碰了＝施工，留在簽架構圖後）；簽圖前這些 view 隨時可整檔重寫——可丟紀律不因為寫成 Vue 就失效。確認完的原型 view 之後接上 API 就是成品的種子。沒有前端骨架才退回單檔 HTML＋假資料；再不行退化成逐屏文字稿確認。**原型的皮照目標 repo 的既有版型**（lean-stack 系＝lean-admin 後台版型，動手前先載 admin-ui skill 參照）——像不像判的是「他未來真的會看到的樣子」，不是我的臨場美術。**確認一輪一屏**：一次只給一個畫面、一題確認，點完這屏才換下一屏——不准一張表單問三個頁面。**每屏開頭在主流程圖上標「你在這裡」**（這屏對應主流程第幾步）——局部確認永遠掛在全貌上，不讓人迷失在單屏裡。
- 收出**不可猜的資料×動作**，並排成**頁面清單**（資料清單＝它的第一欄，不另立檔案）：拿做好的頁走一遍流程，每種資料配列表頁、詳細頁（建立、檢視、編輯都在詳細頁），會被選取的加一個互動元件（對話框、抽屜）；每個資料問一次「要自己的列表／詳細頁，還是在別的畫面的選取框裡出現就夠？」——沒對照，資料會靜靜漏頁（判例：客戶只活在挑選框裡，管理頁沒人問）。選取框也是合法答案，記進頁面清單。**名詞盤點（封物件清單前必做）**：回掃需求方全場原話，**他提過的每個實體名詞都要有下落**——收進資料清單／明確不收（一句為什麼，進暫不實作、逐項勾）／掛 🔴，不准靜靜消失（判例：開場句就有「商品或服務」，商品卻沒進物件清單也沒進任何袋——主檔 vs 自由填會改資料層，是結構題，從沒被正式問過）。點名不解答：「怎麼存」是資料表分水嶺的只點名、帶進架構管理（警戒線：多數小系統 3–7 個物件，明顯更多先檢查是不是把欄位當成物）。不展開欄位、計算、權限、完整狀態機。
- **狀態一物一名**：原型畫面上的狀態顯示（tabs、badge、篩選）一律用狀態的正名——與主流程、之後的狀態機同一組詞，**不得另造口語同義詞**（判例：狀態是草擬／已送出／已成交／沒成，原型列表卻寫「在談」——讀者得自己猜在談＝已送出）。業主口語慣用詞要嘛升格為正名、要嘛不上畫面，不准兩套並行。
- 清結構題（表單／候選形式）；數值題入袋。
- **收斂完成**（依檔位）＝主流程走得完且頁面清單填滿＋資料連續兩輪不變＋結構性 🔴 清零（只剩數值）。**由你主動宣告**，他可否決，否決＝續圈。

## 交接（收斂完成）

三種結果：**未收斂**（保留 GAP 續圈）／**可進架構管理**（三樣→系統總覽；從零系統可接 `intent-to-rules`）／**可進製作**（交對應領域流程，附回溯本包的成功條件與底線）。

**三樣出手前自檢**（總確認表單開出前逐條過；哪條不過就回去補，不是往下走）：

1. **三樣齊全、袋不混**：意圖清單、資料清單、頁面清單都在；暫不實作只收決定（各附一句為什麼）、待回答只收欠帳。
2. **主流程圖是當前版**、照〈圖的紀律〉過出手前品質閘（渲染過、自己看過）。
3. **名詞盤點做過**：需求方全場提過的實體名詞都有下落（收進清單／明確不收／掛 🔴）。
4. **「暫不實作」逐項勾過**——沒逐項勾的取捨回「待回答」，不准被「以上皆對」帶過。
5. **一物一名**：清單、圖、原型上的狀態與資料同一組正名。

**意圖定稿＝三樣**（每樣落進系統總覽的哪幾頁）：①意圖清單（五格表→流程、原則、權限頁）②資料清單（不再改的名詞；就是頁面清單第一欄→資料、關係頁）③頁面清單（每種資料一列：列表頁、詳細頁、選取用的互動元件→頁面頁）。主流程畫在頁面原型裡（每屏「你在這裡」），落流程頁。頁面原型放同一個資料夾當**證據**：只留最新一版、不簽、不拿去施工；原型上有、三樣沒寫的不算數。袋另附：「暫不實作」只收**決定不做的**（各附一句為什麼→範圍界線）；「待回答」＝**還沒答的問題**（起草系統總覽前要補答）。兩者不准混：不做是決定，沒答是欠帳。**整包叫意圖定稿，不准把意圖清單叫成意圖定稿。**

**lean-stack 系 repo（舊管線，待移植）：把意圖定稿寫成 `intents/意圖定稿.md`（五段形：意圖清單／主流程／核心物件＝資料清單／暫不實作／待回答），並跑 `gen-系統總覽.py` 建專案面板 `intents/系統總覽.html`**——整條知識層一頁投影，從這一刻出生、跟著站位長大。 接著**遞棒不斷線**：使用者還在線就出一題「現在就起草設計圖？」——勾了→當場進架構站流程（照 /next 架構站走：問完「待回答」欠帳題 → 起草 `intents/架構圖.md`＋重跑 `gen-系統總覽.py`（總覽頁在意圖定稿落檔時就建了，這裡跟著長大） → 過起草自檢 → 差異簽核：只拍「比意圖定稿多出的判斷」2–5 題）；沒勾或人已離開→下次 `/next` 自動接手。**草稿自動產、簽核永遠是人**——架構圖是第一份正本，增量判斷沒拍過不算存在。其他環境預設對話輸出。
