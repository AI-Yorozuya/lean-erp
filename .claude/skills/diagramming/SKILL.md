# Diagramming：圖的紀律（單一正本）

> 本檔為交付副本（自足）；正本住 ai-yorozuya `jarvis/skills/diagramming/`，改正本→同步這裡。
> 客戶交付場景的渲染管線與語意色細節，正本在 ai-yorozuya 框架文件 §5.9（本 repo 用不到——這裡的圖都屬人面收斂場景）。

## 動筆前三問（先判該不該畫、畫什麼）

1. **一句話講得完就寫句子，不畫圖。** 圖的資格＝讓冷讀者看見「原本得從散文自己拼」的機制；為裝飾而畫的圖是負資產。
2. **先宣告一行：這張圖給誰看、要回答什麼問題**（例：「給業主看：錢從進來到認列只有哪一條路」）。答不出來＝還不知道要畫什麼，先回去想。
3. **畫機制、不畫名字。** 一個標著「快取」的方塊比一句話資訊還少——要畫的是請求穿過它的路徑、它夾在誰跟誰中間、拿掉它哪條邊消失。比較方案時**畫差異**（各方案增刪的那條邊、或前後並排），各畫一個互不相連的方塊＝把選項清單重抄一遍，不是比較。

## 何時亮圖

- **全貌先行**：流程先有一張整條的圖，局部確認／簽核錨在圖上；**只給表格或文字箭頭＝沒交**。圖管全貌理解、表單管逐步拍板，互不取代。
- **圖永遠是當前版**：改了哪步，圖改完重亮再確認——不讓人對著過期的全貌點頭。
- **圖是派生、文字是正本**：改流程先改文字行，圖跟著重畫；圖文不符以文字為準。
- **大圖不硬塞**：節點超過 7±2 就切子圖（per bounded context），總量用表收（基準：top-erp 45 實體不畫一張 ER）。
- **泳道圖單角色群不畫**——泳道的價值在多角色交棒，真長出多角色再加。

## 怎麼畫（mermaid）

- 決策點用**方框**不用菱形（長文菱形撐成大鑽石）；狀態機 `direction TB`（橫排＋複合狀態＋雙向退路必打結）；`curve: linear`；theme base＋自訂色。
- **樣式要真的看得見**：mermaid 叢集外框預設近白——虛線、強調要同時指定 stroke 顏色，畫了看不見等於沒畫（判例：橫切支援虛線框第一版隱形）。
- **邊＝資料或動作的流向**，標籤用動詞（帶入、轉成），不用口語比喻（判例：「住在開新單裡」→「帶入客戶」）；內嵌、附屬這類結構關係寫進節點名，不佔邊標籤。無標籤的邊只說得出「有點關係」——每條邊都要答得出「流的是什麼」。
- **一物一名**：狀態與物件在圖、表、頁面全用同一正名，口語同義詞不上圖（判例：「在談」＝已送出）。
- **編號錨定**：主流程步驟編號（①②③…）是跨圖表的共用鍵——模組表、規格書、局部確認引用同一套編號，不另起爐灶。
- **退路不塞主流程**：主流程圖管走的路，狀態機管退路與逆向邊；兩張各畫、互相指引，不混成一張。
- **圖表相配**：承重的圖配一張解讀表（這張圖要你看見的 2–3 個承重點＋一動牽動什麼）；圖例就地寫在圖旁（「黃＝級聯 hub、紅＝不可逆」），不讓讀者猜色。

## 出手前品質閘（硬流程，逐關過了才准交）

1. **語法必過**：`npx --yes @mermaid-js/mermaid-cli -i 圖.mmd -o 圖.svg`（客戶交付場景帶 `-c/-C` 主題檔）。parse 失敗把錯誤訊息餵回自修，**至多 2 輪**；還不過＝換個畫法重畫，不硬調語法。
2. **自己看渲染結果**（Read 讀 svg、或瀏覽器開 HTML 截圖）：對五件——文字被裁切（CJK 常見）／節點過密打結／方向錯（狀態機橫排）／樣式隱形（虛線沒 stroke）／色違反場景規則。醜圖改到能看才交，**至多 2 輪**，之後留給人回饋。**不盲交原始碼。**
   渲染管道依序：mermaid（mmdc）→ 單檔 HTML 開瀏覽器 → widget；全都沒有才退文字流程圖（退化也要明說是退化）。
3. **CJK 防裁切**：派生頁 CSS 加 `foreignObject { overflow:visible }`（量測字體與顯示字體不同，中文標籤會被剪邊）；標籤精簡、括號註解能短則短。
4. **派生 HTML 內嵌渲染好的 SVG**——不依外網 CDN，側欄預覽與離線都要顯示（判例：CDN 被擋，「圖又不見了」）。md 內保留 ```mermaid fence 給 GitHub 原生渲染，fence 與 `.mmd` 同源回填、不許漂移。

## 基準判例

**人面收斂基準＝lean-stack 報價單知識架構圖修好版**（nolan 認可的品質標竿；`lean-stack/intents/架構圖.md`），好在六處：

1. **一頁看完＋薄度宣言在檔頭**——只寫 AI 猜不到的判斷，「這份變厚就是警訊」。
2. **步驟編號當共用鍵**——主流程圖帶①–⑦，模組對照表的流程欄引用同一套編號；圖與表互相錨定，讀者不用自己對。
3. **退路不塞主流程**——主流程圖管走的路，狀態機管退路與逆向邊，各一張、互相指引（「退路見下方狀態圖」）；狀態機圖旁並列文字版，同源。
4. **模組×頁面圖一模組一色**、橫切支援收虛線框；主流程圖 2–3 色（紫＝主流程、綠＝下游訂單、灰＝旁支）。
5. **決策點方框帶具名出邊**（點結果→成交／沒成），不用菱形。
6. **原則表固定「原則／守什麼／如何守住」三欄**——逐條對回「絕不能發生」；保護方式可連到測試、資料庫限制、權限檢查、操作紀錄或監測，圖、表、文全鏈回四問。

**客戶交付場景參考＝top-erp 知識架構圖**（code-to-intent S5 產物；本機 `jarvis/runs/top-erp/2026-08-11-01/grasp/知識架構圖.md`，runs 不進 git）：鳥瞰先行（黃金路徑一條線，不是全系統盤點）、圖表相配（每張圖配承重點表＋就地圖例）、大圖切子圖（45 實體不畫一張 ER）、每條主張點得回 file:line。
