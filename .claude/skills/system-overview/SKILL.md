# 系統總覽

系統總覽是一個網頁，選單八項，每頁答一個問題：資料頁答有什麼、關係頁答誰引用誰、頁面頁答在哪一頁按什麼、流程頁答按完走到哪一步、權限頁答誰能按、原則頁答什麼不能做、規格頁答怎樣算做對、版本頁答哪一版改了什麼。它是專案負責人跟 AI 一起看的同一份，用白話寫。

**正本只有一個：`系統總覽.json`。** 你只動 json，跑一次產生器；人看 html，html 不手改。

```
專案/
  意圖清單.md、頁面清單.md、原型.html   ← 章 2 交出的
  系統總覽.json      ← 你改這個（正本）
  系統總覽.html      ← 產生器出這個（人看）
```

```
node <skill 所在路徑>/build.cjs <專案資料夾>            # 出 專案/系統總覽.html
node <skill 所在路徑>/build.cjs <json> <出到哪的 html>  # 指定輸出
```

## 輸入（只讀專案資料夾）
- `意圖清單.md`：五件事（誰在做、怎麼做、交出什麼、有什麼特殊規則、什麼一定不能錯），一個角色一欄。
- `頁面清單.md`：每種資料一列：列表頁、詳細頁，會被選取的加互動元件；第一欄就是資料清單；底下列原型上的按鈕。
- `原型.html`：能點的頁面原型。頁、欄位、按鈕以它為準（人在章 2 逐頁看過）；只有原型有的頁（例如報表頁）不進這一版，回報時列出來。

範例專案：lean-erp 的 `intents/`（報價系統），看它的三個輸入怎麼寫就好，不抄它的 json。`build.cjs` 不用讀，這份說明列的就是全部規則。

## 三種模式
- **起草**：讀三個輸入，寫 json，`releases` 第一行 v1「依意圖清單、頁面清單起草」，跑產生器。**起草不寫 `specs`、`tests`**，規格等人挑按鈕再寫。回報格式：先一行產生器印的結果；再把所有 `ai` 逐條列出（哪一頁、中文名加程式名、為什麼這樣推）；最後列只有原型有、這版沒進的東西。
- **改版**：輸入一句新需求或一個決定。先回述：落在哪幾頁、動 json 哪幾筆、哪幾筆是推的、哪幾筆是拍板的；人點頭再只改那幾筆，`releases` 加一行，跑產生器。不准重排整份。回報時列出這次新增的 `ai`。
- **規格**：人指一顆會改資料的按鈕（泳道步驟或頁面動作），或報表頁的查詢。寫一塊 `specs`（動作、欄位、計算、回應）加兩條 `tests`（正常、不能出錯），掛到那顆按鈕的 `spec`，`releases` 加一行。欄位一律 `ref` 到資料頁，資料頁沒有就先補資料頁再寫。回報時列出還沒有任何驗收守著的原則。

## 標記：每一筆是誰講的
能標記的東西（資料、欄位、頁、原則）可以是字串（＝`src`）或物件加 `mark`、`tag`：
- `src`：兩張清單寫的，或原型上看得到的頁、欄位、按鈕、資料（含品項表格這種原型有、清單沒列名的資料）。必填、唯一、系統帶入（單號自動編、日期帶今天，寫 `calc`）照原型填，這些不算推的。字串或沒寫 `mark` 的物件都是 `src`，不用特地寫。
- `ai`：**狀態、原則、算法**這三種東西只認意圖清單：意圖清單五格沒講的，就算原型上有標籤或鎖，也是你推的，標 `ai`（章 2 的原型只定頁和欄位，不定流程和規矩）。另外你自己加的、原型和清單都沒有的資料、欄位、頁，也標 `ai`。`tag` 寫「AI 推的，待確認：為什麼這樣推」。不准把推的標成 `src`。
- `dec`：人拍板的。`tag` 寫「拍板：原因（日期）」。只有人說了才標。

## 一個東西一個名字
角色、模組、資料、欄位、頁、步驟、規格、驗收、原則的 `id` 就是程式名，全站不重名；產生器檢查，重了不出頁。回報時寫中文名加程式名，例如「報價單詳細 quote_detail」。

## `系統總覽.json` 欄位

| 鍵 | 內容 | 從哪裡來 |
|---|---|---|
| `system` | `name`、`purpose`（一句：幫誰、做什麼、交出什麼；網頁不顯示，給改版時判斷新需求在不在範圍） | 意圖清單 |
| `roles[]` | `id`、`name` | 意圖清單・誰在做 |
| `modules[]` | `id`、`name`（後台選單群組名，例：銷售管理）、`roles[]`（誰用） | 一群資料一個模組 |
| `data[]` | `id`、`module`、`name`、`fields[]`、`refs[]`、`mark`、`tag`（整種資料是你加的才標） | 頁面清單第一欄，加原型上有的表格（例如報價單詳細裡的品項）。意圖清單的名詞頁面清單沒對應資料時（例如價目表），看原型它落在哪個欄位（商品的單價） |
| `data[].fields[]` | `text`、`id`（同一種資料裡不重名）、`type`（只用：文字、數字、金額、日期、選項、是否、引用）、`required`、`unique`、`calc`（系統算出）、`ref`（引用型別：指向哪種資料的 id）、`options`（選項型別：每個值 `{text, id}`，`id` 用英文，例 `draft`）、`state: true`（狀態欄位；它的 `options` 就是這種資料的狀態，不另寫）、`mark`、`tag` | 原型上的欄位。客戶頁上「幾筆報價、最近一張」這種從別的資料反算出來的顯示不算欄位，不放 |
| `data[].refs[]` | 寫在引用者身上：報價單引用客戶，寫在報價單的 `refs`，`to: "customer"`；`text`（一句白話講關係）、`part: true`（從屬，例如報價單品項從屬於報價單） | 原型上哪一頁選了哪種資料；哪張表格長在哪一頁裡 |
| `flows[]` | 只有帶狀態的資料才填一條。`data`、`lanes[]`（角色 id，只有人）、`steps[]`：這種資料從開始到最後狀態會按到的按鈕，含選取步驟。每步 `id`、`lane`（系統外的步驟填最後按的人）、`label`（按鈕名）、`page`（在哪一頁按；系統外的步驟不寫）、`after`（接在哪一步後，預設前一步）、`from`／`to`（狀態，寫選項 id；只在狀態改變的那一步寫，第一個狀態掛在第一次存下這筆資料的那一步、只寫 `to`；不改狀態的步驟不寫）、`lock`（進這個狀態後不能改，寫一句）、`spec`、`opens`（開哪個互動元件）、`dashed`（系統外的動作，例如傳給客戶） | 意圖清單・怎麼做、交出什麼：那一格的每個動作落成一步；「交出什麼」是最後一步（傳給客戶，`dashed`）。狀態的轉換是你推的，`ai` 標在狀態欄位上 |
| `pages[]` | `id`（例 `quote_detail`）、`data`、`kind`（`list`／`detail`／`widget`／`report`）、`name`、`actions[]`、`used_by[]`（互動元件被哪些頁用）、`roles[]`（這頁的角色跟模組的不同時才寫）、`mark`、`tag` | 頁面清單 |
| `pages[].actions[]` | 會改已存資料的按鈕：儲存、編輯、刪除、確認建立、匯出這種。不列：搜尋、取消、返回、開新單（只是打開空白詳細頁）、還沒存的草稿上的增減和移除。泳道步驟指到這頁的會自動出現在頁面頁，不用再列；沒有的頁省略這個鍵。可寫 `{label, roles, spec}` | 頁面清單底下的按鈕 |
| `principles[]` | `id`（例 `rule_sent_locked`）、`module`、`text`（一句白話）、`mark`、`tag`。意圖清單「特殊規則」「一定不能錯」每一句一條；原型上的鎖、擋各一條，標 `ai`（已送出不能編輯、沒選客戶不能建立）；單純的必填（名稱不能空白）用欄位的 `required`，不另立原則。清單和原型都沒有的不憑空加 | 意圖清單；原型上的鎖 |
| `specs[]` | `id`、`title`、`action`、`fields[]`（`{ref: '資料.欄位', note}`）、`calc`、`calc_rules[]`（計算依據的原則 id）、`response`。權限不寫（產生器從模組的角色和泳道的道算） | 規格模式 |
| `tests[]` | `id`、`spec`、`kind`（`ok`／`no`）、`text`（怎麼做、看到什麼）、`guards[]`（守哪幾條原則；沒有就空陣列，不硬湊） | 規格模式 |
| `releases[]` | `v`、`date`、`what`、`who`（起草寫「AI 起草」；拍板寫誰、原因）、`changes[]`（這版動到的 id：資料、`資料.欄位`、頁、步驟、原則、規格、驗收、角色、模組；起草那版列角色、模組、資料、頁（含互動元件）、原則，不逐欄位列；每個 id 產生器都會驗），新的在前；`date` 寫今天 | 每次改版加一行 |

## 交回前自檢（任何一項不過就不交）
1. 意圖清單每一格、頁面清單每一頁、每種資料在 json 裡都有落點；原型有、頁面清單沒有的，列在回報裡。
2. 所有 `ai` 都有 tag 寫為什麼推；所有 `dec` 都有原因和日期；沒有人說的話不標 `dec`。
3. 這版的 `changes` 列齊。
4. 有 `specs` 的：欄位都 `ref` 到資料頁、計算依據都在 `calc_rules`、兩條 `tests` 都在。
5. `releases` 第一行就是這次；沒有「簽核」字樣。
6. 產生器跑過、沒報錯。

網頁長什麼樣、怎麼排版，見 `產生器說明.md`，寫 json 不用讀。產生器印的「幾頁」不含互動元件。
